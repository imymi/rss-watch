# RSS Watch v0.3.0-rc.1

首个 Go 候选版，面向 Linux AMD64 和 ARM64 的 Docker Compose 安装。一个镜像分别运行 Web 和 Worker。现有订阅、规则、机器人凭据、文章指纹、待发队列和推送历史可以从 Python v0.2.0 的原卷接续使用。

## 变化

- Go Web 沿用原有中文管理界面和 API，可使用现有管理员帐号登录。保留订阅和规则管理、飞书机器人、推送历史、运维操作和 ZIP 备份恢复。
- Go Worker 保留 RSS/Atom 条件请求、每个订阅源的首次抓取基线、文章去重、签名推送、限流和重试。进程中断后恢复未完成的任务，沿用原事件编号。
- Go 和 Python v0.2.0 使用同一个 SQLite schema 2。Go Web 可以导入 schema 1 和 schema 2 的 Python ZIP 备份，Python v0.2.0 也能读取 Go 导出的 schema 2 ZIP。
- Go 后台和容器的 `--version` 显示 `v0.3.0-rc.1`。继续通过 Web 或管理 API 操作订阅、队列和备份。依赖 Python 管理 CLI 或原生 systemd 安装器的环境继续使用 Python v0.2.0。

## 升级范围

原卷切换的基准为 Docker Compose 上的 Python v0.2.0。保留原项目名、SQLite 和凭据卷，切换前下载包括活动机器人凭据的完整 ZIP。先按[升级与回退步骤](../go-compose-migration.md)核对两个镜像和待发任务，再恢复监控。

推送仍采用至少一次投递。远端可能已接收而本地未收到响应；遇到这种情况，用事件编号核对后再决定是否重试。直接回退并复用当前卷可保留 Go 运行期间产生的数据；从旧备份恢复会丢失备份之后的记录，期间已送达的消息可能再次发送。

## 验收

解析对比覆盖 33 个合成样本和 9 份脱敏订阅。Web 与 Worker 集成测试覆盖登录、抓取、去重、重试、进程重启和双向 ZIP 兼容。Compose 演练在两次切换时核对原卷、凭据文件校验值和事件编号，并在回退后强制重新解析既有文章，检查重复推送。[演练记录与复现命令](../../tests/compose/README.md)

候选版验证工作流包括 Go 竞态回归和两个原生架构的镜像构建与升级回退作业。镜像仅加载到作业的临时 Docker 引擎。该候选版当前处于待发布状态。[候选版 CI 配置](../../.github/workflows/go-release-candidate.yml)
